About the pins

{{if .KeyPin}}

This server uses its own self-signed certificate, so no public certificate authority vouches for it. Instead the agent checks two fingerprints of it:

  • Key pin {{.KeyPin}}: a hash of the certificate's public key. curl --pinnedpubkey checks it. -k turns off curl's usual check against certificate authorities, and the pin replaces it: curl refuses any other server.
  • Certificate pin {{.CertPin}}: a hash of the whole certificate. The keydrop CLI checks it on every connection.

Both are public and safe to share. They let the agent check it's talking to this server before it installs anything. They don't make the agent trustworthy: what limits an agent is your approval of its pairing, the permission you give it (read, add or write), its namespaces, and the log of everything it does.

{{else}}

This server's certificate is one the agent's system already trusts, so curl and the CLI check it the normal way and there's nothing to pin.
